Программное обеспечение (ПО) является одним из частей АСУ РНТТМ. Оно позволяет организовать выполнение широкого спектра задач: от управления движением до взаимодействия с внешней средой. Это нашло свое отражение в множестве регламентирующих документов \cite{gostESPD, gost_24836_81, gost_27696_88, gost_60_0_0_1_2016, gost_60_0_0_2_2016, gost_60_0_0_3_2016, gost_60_0_0_22_2025, gost_60_0_0_23_2025, gost_60_0_7_1_2016, gost_60_0_7_6_2025, gost_60_1_2_1_2016, gost_60_1_2_2_2016}.

\nomenclature{ПО}{программное обеспечение\nomrefpage}

Место ПО в АСУ РНТТМ представлено на рис.\ \cref{fig:po_drawio} и \cref{fig:os_drawio} и характеризуется многоуровневым принципом \cite{OSTanenbaum}, что позволяет разделить ответственность между компонентами и повысить надежность системы. Рассмотрим классы ПО:

\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item операционные системы (ОС);

	\item общее программное обеспечение (ОПО);

	\item специальное программное обеспечение (СПО).
\end{itemize}

\nomenclature{ОС}{операционная система\nomrefpage}
\nomenclature{ОПО}{общее программно обеспечение\nomrefpage}
\nomenclature{СПО}{специальное программно обеспечение\nomrefpage}

Наибольшее распространение для решения прикладных задач в разработке и производстве РНТТМ занимают unix-подобные ОС, т.\ к. они имеют ряд преимуществ, главным из которых является открытый исходный код, доступный для получения и использования (изменения в своих целях) каждому \cite{LinuxKetov}.

ОС для РНТТМ должны соответствовать жестким требованиям \cite{confbib3, bib1}:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item \textit{процессы}: изоляция задач, планирование с приоритетами;
	\item \textit{ядро}: минимизация латентности, поддержка реального времени;
	\item \textit{драйвера устройств}: прямое управление аппаратурой.
\end{itemize}

Примерами таких ОС, применяемых в разработке автоматизированных РНТТМ являются:

\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item \textit{Linux с дополнением PREEMPT\_RT}\ \footnote{\ Патч для ядра Linux, уменьшающий задержки планирования.}: открытость, поддержка широкого спектра устройств;
	\item \textit{QNX}\ \footnote{\ Микроядерная ОС с сертификацией для медицинских и промышленных систем.}: детерминированное выполнение, отказоустойчивость;
	\item \textit{VxWorks}\ \footnote{\ ОС реального времени, используемая в аэрокосмической отрасли.}: сертификация DO-178C для критических задач.
\end{itemize}

ОПО включает базовые сервисы для управления ресурсами системы \cite{LinuxWard}:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item загружаемые модули ядра;
	\item системные библиотеки;
	\item утилиты мониторинга и др.
\end{itemize}

СПО включает алгоритмы управления движением, обработки данных с датчиков и взаимодействия с исполнительными механизмами (рис.\ \cref{fig:rms_drawio}). Основные требования к нему:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item \textit{детерминизм}: выполнение операций за строго заданное время;

	\item \textit{отказоустойчивость}: автоматическое восстановление после сбоев;

	\item \textit{интеграция с внешними системами}: предоставление интерфейса программного приложения (API) для доступа к ресурсам РНТТМ;

	\item \textit{интеграция с ОС}: использование API ОС для доступа к ресурсам.
\end{itemize}

\nomenclature{API}{Application Programming Interface, интерфейс программного приложения\nomrefpage}

Рассмотренные классы ПО обеспечивают базовый функционал для отдельных компонентов системы, однако управление группой взаимодействующих РНТТМ требует принципиально иного подхода.

При этом, для этого не требуется внесения конструктивных изменений в базовое шасси или рабочее оборудование РНТТМ. Необходимые изменения будут носить \textbf{системный и программный характер}:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item переход от централизованной архитектуры управления к децентрализованной -- отсутствие единого лидера, каждая РНТТМ автономна;
	\item реализация на бортовых вычислителях функций полезности, а также алгоритмов поиска байесовских равновесий Нэша;
	\item модификация протоколов обмена данными -- передача только скалярных значений (цен, приоритетов) для минимизации трафика.
\end{itemize}

Таким образом, возможное решение будет адаптировано к существующим паркам машин путем обновления программного обеспечения без доработки механической части.

Координация комплекса роботизированных РНТТМ в реальном времени представляет собой задачу:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item \textit{масштабируемости}: синхронизация десятков или сотен РНТТМ;

	\item \textit{ресурсных конфликтов}: распределение зон ответственности, энергии и~маршрутов;

	\item \textit{динамической адаптации}: перераспределение задач при отказах/вмеша-тельствах.
\end{itemize}

Данная проблема решается в рамках рассмотрения РНТТМ как элемента \textit{групповых систем} (ГС) \cite{vakbib1}, где каждая РНТТМ выступает как:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item автономная РНТТМ с локальными целями;

	\item участник подмножества ГС с глобальной задачей;
\end{itemize}

\nomenclature{ГС}{групповая система\nomrefpage}

Реализация различных сценариев применения РНТТМ в ГС требует специализированного СПО, включающего:
\begin{itemize}[beginpenalty=10000, midpenalty=10000, wide=\parindent, leftmargin=0pt]
	\item математические модели распределенного принятия решений;

	\item алгоритмы оптимизации на графах зависимостей;

	\item механизмы балансировки централизованного и децентрализованного управления.
\end{itemize}
