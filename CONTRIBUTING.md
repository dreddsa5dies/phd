# Внесение предложений и сообщения о проблемах

Благодарим за интерес к диссертационной работе!
Если вы заметили неточность, опечатку, ошибку в программном коде или хотите предложить улучшение, мы будем рады вашей помощи.

---

## Как сообщить о проблеме

Если вы столкнулись с проблемой при компиляции диссертации, работе программного кода или заметили ошибку в тексте, пожалуйста, создайте **Issue** в репозитории.

**Желательно** при описании проблемы:
- Четко сформулировать, в чем заключается проблема.
- Указать, в каком файле и в каком месте она возникает.
- Для ошибок компиляции LaTeX приложить **минимальный рабочий пример** (Minimal Working Example) - небольшой фрагмент кода, который воспроизводит ошибку.
- Для проблем с программным кодом (Go) описать шаги воспроизведения, ожидаемое и фактическое поведение.

Это поможет быстро разобраться и исправить недочет.

---

## Как предложить изменения

Вы можете внести правки как в текст диссертации (файлы `.tex`), так и в программную реализацию (каталог `code/`). Для этого используется стандартный GitHub-процесс **Fork → Pull Request**.

### Простые правки (опечатки, мелкие уточнения)

1. Сделайте **Fork** репозитория (кнопка в правом верхнем углу).
2. В своем форке найдите нужный файл и нажмите на карандаш (Edit this file).
3. Внесите изменения, сохраните коммит.
4. На странице вашего форка появится кнопка **New Pull Request** - нажмите ее и создайте запрос на слияние.

### Сложные правки (изменение структуры, добавление глав, правка шаблона)

1. Склонируйте репозиторий локально.
2. Внесите изменения в файлы.
3. Проверьте, что диссертация компилируется без ошибок:
   - Используйте компиляторы `pdflatex`, `xelatex` и `lualatex`.
   - Проверьте работу с библиографией через `bibtex` и `biblatex`.
   - Для автоматической проверки можно выполнить `make examples` (если установлен `make`).
4. Для изменений в программном коде (Go) убедитесь, что:
   - Код компилируется (`go build`).
   - Все тесты проходят (`go test ./...`).
   - Код отформатирован согласно стандарту `go fmt`.
5. Создайте Pull Request с описанием внесенных изменений.

## Стилистические требования

Чтобы поддерживать единообразие, пожалуйста, соблюдайте следующие правила при внесении правок:

### Для LaTeX-файлов
- Отступы - **4 пробела** (в соответствии с настройками `latexindent`).
- Не оставляйте пробелы в конце строк.
- В конце файла должна быть пустая строка.
- Используйте кодировку **UTF-8**.
- Перевод строк - **LF** (не CRLF).

### Для кода на Go
- Следуйте стандартному стилю языка (`gofmt`).
- Используйте осмысленные имена переменных и функций.
- Документируйте экспортируемые элементы.
