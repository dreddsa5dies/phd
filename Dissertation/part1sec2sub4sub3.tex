Программное обеспечение (ПО) является одним из частей АСУ НТТС. Оно позволяет организовать выполнение широкого спектра задач: от управления движением до взаимодействия с внешней средой.

\nomenclature{ПО}{программное обеспечение\nomrefpage}

Место ПО в АСУ НТТС представлено на рис.\ \cref{fig:po_drawio} и \cref{fig:os_drawio} и характеризуется многоуровневым принципом \cite{OSTanenbaum}, что позволяет разделить ответственность между компонентами и повысить надежность системы. Рассмотрим классы ПО:

\begin{itemize}
	\item операционные системы (ОС);

	\item общее программное обеспечение (ОПО);

	\item специальное программное обеспечение (СПО).
\end{itemize}

\nomenclature{ОС}{операционная система\nomrefpage}
\nomenclature{ОПО}{общее программно обеспечение\nomrefpage}
\nomenclature{СПО}{специальное программно обеспечение\nomrefpage}

Наибольшее распространение для решения прикладных задач в разработке и производстве НТТС занимают unix-подобные ОС, т.\ к. они имеют ряд преимуществ, главным из которых является открытый исходный код, доступный для получения и использования (изменения в своих целях) каждому \cite{LinuxKetov}.

ОС для НТТС должны соответствовать жестким требованиям \cite{confbib5}:
\begin{itemize}
	\item \textit{процессы}: изоляция задач, планирование с приоритетами;
	\item \textit{ядро}: минимизация латентности, поддержка реального времени;
	\item \textit{драйвера устройств}: прямое управление аппаратурой.
\end{itemize}

Примерами таких ОС, применяемых в разработке автоматизированных НТТС являются:

\begin{itemize}
	\item \textit{Linux с дополнением PREEMPT\_RT}\ \footnote{\ Патч для ядра Linux, уменьшающий задержки планирования.}: открытость, поддержка широкого спектра устройств;
	\item \textit{QNX}\ \footnote{\ Микроядерная ОС с сертификацией для медицинских и промышленных систем.}: детерминированное выполнение, отказоустойчивость;
	\item \textit{VxWorks}\ \footnote{\ ОС реального времени, используемая в аэрокосмической отрасли.}: сертификация DO-178C для критических задач.
\end{itemize}

ОПО включает базовые сервисы для управления ресурсами системы \cite{LinuxWard}:
\begin{itemize}
	\item загружаемые модули ядра;
	\item системные библиотеки;
	\item утилиты мониторинга и др.
\end{itemize}

СПО включает алгоритмы управления движением, обработки данных с датчиков и взаимодействия с исполнительными механизмами (рис.\ \cref{fig:rms_drawio}). Основные требования к нему:
\begin{itemize}
	\item \textit{детерминизм}: выполнение операций за строго заданное время;

	\item \textit{отказоустойчивость}: автоматическое восстановление после сбоев;

	\item \textit{интеграция с внешними системами}: предоставление интерфейса программного приложения (API) для доступа к ресурсам НТТС;

	\item \textit{интеграция с ОС}: использование API ОС для доступа к ресурсам.
\end{itemize}

\nomenclature{API}{Application Programming Interface, интерфейс программного приложения\nomrefpage}

Примеры реализаций СПО для НТТС:
\begin{itemize}
	\item \textit{ROS 2}\ \footnote{\ \ Robot Operating System 2 -- фреймворк для разработки робототехнических систем с поддержкой реального времени.}: поддерживает распределенные вычисления и QoS;
	\item \textit{AUTOSAR}\ \footnote{\ Стандарт для автомобильной электроники с разделением на прикладной и базовый уровни.}: обеспечивает модульность и переносимость;
	\item \textit{СПО на базе ИИ}: нейросетевые модели для прогнозирования состояний.
\end{itemize}

Рассмотренные классы ПО обеспечивают базовый функционал для отдельных компонентов системы, однако управление группой взаимодейст-вующих НТТС требует принципиально иного подхода.

Координация групп роботизированных НТТС в реальном времени представляет собой задачу:
\begin{itemize}
	\item \textit{масштабируемости}: синхронизация десятков или сотен НТТС;

	\item \textit{ресурсных конфликтов}: распределение зон ответственности, энергии и~маршрутов;

	\item \textit{динамической адаптации}: перераспределение задач при отказах/вмеша-тельствах.
\end{itemize}

Данная проблема решается в рамках рассмотрения НТТС как элемента \textit{групповых систем} (ГС) \cite{vakbib1}, где каждый НТТС выступает как:
\begin{itemize}
	\item автономный НТТС с локальными целями;

	\item участник подмножества ГС с глобальной задачей;
\end{itemize}

\nomenclature{ГС}{групповая система\nomrefpage}

Реализация различных сценариев применения НТТС в ГС требует специализированного СПО, включающего:
\begin{itemize}
	\item математические модели распределенного принятия решений;

	\item алгоритмы оптимизации на графах зависимостей;

	\item механизмы балансировки централизованного и децентрализованного управления.
\end{itemize}
