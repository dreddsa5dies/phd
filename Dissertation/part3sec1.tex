Для практической верификации разработанной математической модели и~алгоритмов многозадачной координации РНТТМ разработано программное средство на языке программирования Go\footnote{\  исходный код и описание размещено на \url{https://go.dev}}. На программное средство получено Свидетельство о государственной регистрации программы для ЭВМ \cite{progbib1} (приложение~\ref{app:register_code_1}). Полный текст программного средства для самостоятельного проведения эксперимента или предложений для апробации размещен по общедоступному адресу в сети Интернет на \url{https://github.com/dreddsa5dies/phd/Dissertation/code} и в приложении \ref{app:code}.

Выбор данного языка программирования обусловлен рядом его фундаментальных преимуществ, критически важных для построения надёжных, производительных и~масштабируемых систем управления роботизированными группами, как это детально описано в работах \cite{GoPractice, GoProfessional, GoLangDonovan, GoLangSumm}. Одновременно с этим, автор имеет большой опыт\footnote{\  программы с открытым исходным кодом размещены на \url{https://github.com/dreddsa5dies} \cite{habr2020hack}, коммерческие продукты разрабатывались в компаниях Qtech и YADRO} в написании распределённых и~эффективных программных средств и~систем на этом языке программирования высокого уровня. Кроме озвученных фактов, имеется еще ряд безусловных преимуществ.

Так, Go изначально спроектирован для создания высоконагруженных сетевых сервисов и~распределенных систем. Имеет встроенную поддержку конкурентности через механизм горутин (goroutines) и каналов (channels) \cite{GoLangDonovan}, что позволяет просто и эффективно моделировать поведение множества автономных РНТТМ, действующих параллельно и взаимодействующих друг с другом. Это идеально соответствует задаче моделирования децентрализованной координации, где каждая машина принимает решения независимо, но с учетом состояния группы.

Во-вторых, язык обеспечивает исключительную производительность, близкую к C/C++, при этом сохраняя простоту синтаксиса и скорость разработки, характерную для интерпретируемых языков \cite{GoProfessional}. Это позволит реализовать вычислительно интенсивные симуляции с большим количеством итераций и машин за приемлемое время, что является ключевым требованием для проведения серийных экспериментов и получения статистически значимых результатов.

В-третьих, Go обладает превосходной поддержкой кроссплатформенной компиляции \cite{GoLangSumm}. Это означает, что разработанная симуляционная среда может быть собрана и запущена без изменений на различных операционных системах, что значительно упрощает ее распространение и использование, а~также потенциальную интеграцию с различными аппаратными платформами (см.~подраздел~\ref{subsec:ch1/sec2/sub4}).

Наконец, статическая типизация и строгая система компиляции Go \cite{GoPractice} способствуют созданию более надежного и предсказуемого кода. Это критически важно для научных исследований, где воспроизводимость результатов является основополагающим принципом. Компилятор выявляет множество потенциальных ошибок на этапе сборки, что снижает вероятность возникновения трудноуловимых багов в процессе выполнения симуляций.

Наиболее существенным недостатком использования этого языка программирования в части, касающейся применения в РНТТМ, является работа планировщика языка Go и использования механизма <<остановки>> для сборки неиспользуемых объектов в памяти ОС. Это значит, что его нельзя применять в~процессах, связанных с непосредственной опасностью для людей и окружающего мира. Для этого стоит применять только ОС реального времени и языки программирования без временных пауз. Но это не относится теме исследования и применение Go целесообразно для проведения эксперимента.

Аналитический модуль позволяет генерировать сводные отчеты в формате CSV\footnote{\  простой табличный формат описания данных} и формирует результаты в виде графиков для наглядного сравнения эффективности различных стратегий.

Модуль <<Стратегии координации>> реализуют интерфейс <<Strategy>> (лист.~\ref{lst:strategy}), что позволяет легко добавлять новые алгоритмы распределения задач и сравнивать их в единой среде используя одинаковые метрики (лист.~\ref{lst:metrics}). Каждая стратегия должна удовлетворять требованиям этого интерфейса, т.\ е. запускаться, принимая набор машин и задач, и~возвращать метрики для последующего анализа. Метод String() предназначен для возврата наименования стратегии.

		type Metrics struct {
			// Общее количество задач всего
			TotalTasks int `json:"totalTasks"`
			// Общее количество машин всего
			TotalMachine int `json:"totalMachine"`
			// Общая энергоемкость машин

			TotalEnergyTasks float64 `json:"totalEnergyTasks"`
			// Список задач
			AllTasks []models.Task `json:"allTasks"`
			// Общее время выполнения
			TotalTime string `json:"totalTime"`
			// Метрики каждого шага
			StepMetric []StepMetrics `json:"stepMetrics"`
		}

		type StepMetrics struct {
			Step int `json:"step"` // Номер прогона
			// Количество выполненных задач
			LenTasksDone int `json:"lenTasksDone"`
			// Перечень исполненных задач по ID
			TasksDone []string `json:"tasksDone"`
			// Энергозатраты машин
			EnergyUsed float64 `json:"energyUsed"`
			// Не исполненные задачи
			LenNotExecTasks int `json:"lenNotExecTasks"`
			// Реальное время выполнения шага
			RealTime string `json:"realTime"`
		}
	\end{lstlisting}
